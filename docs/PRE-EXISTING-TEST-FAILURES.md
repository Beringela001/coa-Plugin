## A. Harness — unbuilt WordPress core (18 errors)

Every failure here is the same missing file:

```
include(/tmp/wordpress/wp-includes/assets/script-loader-react-refresh-entry.php):
Failed to open stream: No such file or directory
```

`bin/install-wp-tests.sh` copies `src/` out of the `wordpress-develop` tarball,
which ships **unbuilt** — that asset is generated by WordPress's own build step.
Any test that renders a page or enqueues scripts dies in `set_up()`.

| Test | File:line |
|---|---|
| `COA_5_Product_Carousel_Test` — all 16 tests | `test-coa-5-product-carousel.php:17` |
| `Frontend_Test::test_archive_empty_whitespace_matching_missing_and_cleared_search_results` | `test-frontend.php:166` |

Plus one admin-context omission of the same kind:

| Test | File:line | Message |
|---|---|---|
| `COA_5C_Dashboard_Test::test_registration_title_and_authorized_widget_visibility` | `test-coa-5c-dashboard.php:33` | `Call to undefined function wp_add_dashboard_widget()` — lives in `wp-admin/includes/dashboard.php`, not loaded |

**Disposition:** fix CI, not the tests. Either build WordPress after extracting,
or install core from the release zip instead of the develop tarball.

## E. Genuinely stale — the code deliberately changed (19)

### E1. Tests that encode a REST policy the plugin intentionally reversed

Versions 0.5.6–0.5.10 deliberately widened the REST-writable meta list so the
ops app could populate a complete record. These tests assert the **old** policy —
that those keys are absent from REST. They are not bugs; they are outdated
requirements.

## Suggested order

1. **Fix CI first** (buckets A–C, 32 rows). Build WordPress properly or install
   from the release zip; add a shared attachment fixture; flush rewrites. That
   likely clears half the list without touching a single assertion.
2. **Re-measure.** The remaining count is the real technical debt.
3. **Decide the REST policy** (E1) — that is a product decision, not a test fix.
4. **Delete bucket D**, or rewrite the rendered-HTML ones against view models.
5. **Triage E2** one at a time.

## Reproducing

```bash
cd pepselect-coa-archive
composer install
bin/install-wp-tests.sh wordpress_test root root 127.0.0.1 6.5.5
WP_TESTS_DIR=/tmp/wordpress-tests-lib vendor/bin/phpunit --testdox
```

`bin/ci-failure-index.py` turns the JUnit log into the one-line-per-failure index
this document was built from.
